# CS-330-Computational-Graphics-and-Visualization

When I approach software design, my first step is understanding all of the entities involved and what they should do.  This helps me decide what objects need to be create and what methods they need.  In this particular project, I needed to make use of those entities and methods to create a three dimensional scene.  I initially coded several objects before running the program to see the results.  One of the textures was formatted incorrectly, so that texture, and all textures that followed, failed. It took some time to find and fix the issue.  From there, I decided to work incrementally, adding one shape, texture or material at a time.  This way, if one particular piece was not working properly, it was easier to find and fix.  I believe this methodical approach takes more time early on, but saves time troubleshooting in the end.  

Consistency is key in coding.  Arranging sections of code so that they are formatted the same makes reading the code much simpler.  I used this approach when coding individual objects, so that when changes were needed later on, the object in question was easier to find.  My mantra was Code, Test, Revise.  This made the process iterative.  I also made a more concerted effort to comment as I coded.  This, again, makes finding and fixing errors much simpler.  

My goal is to transition to a career in either software development or data analysis.  Computer science is a requirement for both of those goals.  While I do not plan to work explicitly in graphics or visuals, I know that data analysis does involve visualizations.  Beyond that, my work on this project and others in this course, I have improved my knowledge base in C++ and refined my ability to write function, organized, and reusable code.
